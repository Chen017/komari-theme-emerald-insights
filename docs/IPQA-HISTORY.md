# IPQA 历史时间轴与快照对比

进入 `/ip-quality/:uuid`，选择「历史分析」即可查看所有项目的历史。也可以在基本信息、风控评分、风险因子、流媒体与 AI、邮件与黑名单标签页下展开对应的历史分析。IPv4 与 IPv6 独立展示。

## 独立时间轴

| 项目        | 使用的每日归档字段                                        |
| ----------- | --------------------------------------------------------- |
| IP 类型     | `info.type`、`type.usage`、`type.company`，包括每个数据源 |
| 风险评分    | `scores`，复用既有评分分类与 `classifiedScores`           |
| 风险因子    | `factors` 中的因子与各引擎结果                            |
| 流媒体与 AI | `media` 中每项服务的解锁状态、方式与地区                  |
| DNSBL       | `mail.DNSBlacklist`，包括命中数与检测总数                 |
| 邮件连通性  | `mail` 中除 DNSBL 以外的检测项目                          |
| IP 归属     | IP、国家、地区、城市、ASN、ISP、组织机构                  |

每个项目分别识别变化日，因此风险评分每日波动不会挤占流媒体的关键日期。默认最多展示 8 个日期，沿用 IPQA 脚本的关键帧策略：

1. 保留范围首尾日期和实际属性变化日。
2. 若变化日超过可显示的数量，只在变化日中选取代表日期，同时保留首尾；界面会提示折叠了多少变化日。
3. 若仍有空位，在最大的日期索引间隙中补入稳定日期。
4. 「展开完整时间轴」可以显示当前范围的全部日期，未抽中的变化不会被删除。

所有已加载日期都参与变化检测，然后才进行展示采样。采样不会提前跳过归档读取。时间范围支持最近 7 天、最近 30 天、全部已加载日期，以最新归档日为基准。

## 快照对比

「对比前」「对比后」可以任选两个已加载日期，也支持交换顺序或比较同一天。默认只显示变化字段，可勾选「显示未变化项目」。点击时间轴上的「对比变化前后」会选中该变化日和它的前一个归档日；点击日期本身会打开当日完整快照。

桌面端使用差异表，手机端使用前后值并排卡片。风险等级与服务状态沿用既有颜色和解析规则，包括 DNS 解锁、受限服务、TikTok 的 ALISG 地区等；不会将 IPv6 或跨协议汇总结果混入 IPv4。

## 数据边界与兼容性

- 复用现有插件的每日双栈归档 API、日期分页、HTTP/RPC 回退，无需更换采集脚本或升级插件。
- 每日归档只代表当天同步的一个快照，不代表脚本中的每一次日内采集；日内变化需查看原始 IPQA 文件。
- 首次仅加载已有日期页（默认最近 30 个归档日），「加载更早归档」继续向前分页。页面会明确提示是否还有更早日期。
- 展开历史分析后才读取历史快照，每轮最多 4 个并发请求；成功结果在当前页面内复用，失败日期可单独重试。
- 缺失归档不是正常检测结果。读取失败和空归档显示为不可用，不据此推测跨空缺的变化。归档存在但没有选定协议时，会明确标记该日无 IPv4/IPv6 报告。
- 只比较项目属性，忽略时间戳、归档 ID 等采集元数据；布尔字符串和同值的数字/字符串评分不会制造变化。未来服务的未知状态仍保留原值。
- 评分阈值、风险等级和流媒体解析复用主题既有 helpers；关键变更提示复用归档中的 `changesFromPrevious`，不在前端另写一套告警判定。
- 共享的 `projectSnapshot` / `compareSnapshots` 同时用于采样、历史表与两日差异，避免三套比较规则。历史属性变化不等于风险告警，例如同一风险等级内的评分波动也会显示。
- 页面末尾近期语义记录沿用插件返回的范围（当前插件最近 30 个归档日）；更早已加载日期的属性变化由上方时间轴展示。

## 本地 beta 包

```sh
bun run build:beta
```

构建执行 Vue/TypeScript 检查与 Vite beta 模式，生成 `komari-theme-emerald-insights-beta-<sha>.zip`。压缩包内的主题名称标注 `(Beta)`，manifest 和网页显示相同的 `2.0.4-beta.ipqa-history.g<sha>` 版本，便于识别与追溯；Windows 桌面存在时会复制同名 beta 包。

源文件 `package.json` 和 `komari-theme.json` 的正式版本保持不变；本地构建不会创建 tag、调用发布脚本或创建 GitHub release。常规构建的包名与 manifest 约定保持不变。仅修改本功能并推送时不会触发基于正式版本变动的发布。
